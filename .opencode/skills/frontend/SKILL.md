# Frontend conventions

The frontend lives in `/app/frontend`. Stack: Vite + React 19 + TypeScript, TanStack Router & Query, Tailwind v4, shadcn-style components built on `@base-ui/react`, API client generated by orval, linted with oxlint, tested with vitest.

## Naming

- Do not use abbreviations when naming variables, parameters, fields, or methods. Use full, descriptive names (e.g. `directory` not `dir`, `extension` not `ext`).

## Tooling & commands

- Package manager: **pnpm** (workspace via `pnpm-workspace.yaml`).
- `pnpm dev` — Vite dev server on port 5000.
- `pnpm build` — runs `gen:api` then `tsc -b && vite build`.
- `pnpm lint` — oxlint (auto-fix is `oxlint --fix`).
- `pnpm format` — format code.
- `pnpm test` / `pnpm test:watch` / `pnpm test:ui` — vitest. See the `frontend-tests` skill.
- `pnpm gen:api` — regenerates the typed API client from `../ImageShare/openapi.json`.

## Project structure (place files by feature)

- `src/routes/` — TanStack Router file-based routes (plugin generates `src/routeTree.gen.ts`; do not hand-edit the generated tree).
- `src/components/ui/` — shadcn-style primitives (`button`, `carousel`, `input`, `label`, ...).
- `src/components/` — feature components.
- `src/lib/api/` — API layer: `generated/` (orval output, do not edit), hand-written wrappers, the fetch mutator, and URL builders.
- `src/lib/` — non-API utilities (`theme.ts`, `utils.ts`).
- `src/test/` — test setup and shared test helpers.

Import alias: **`@`** → `src/` (configured in `vite.config.ts` and `tsconfig`). Prefer `@/lib/...` over relative paths.

## API client (orval + TanStack Query)

- Config is in `orval.config.ts`. Input is the backend `openapi.json`; output is `src/lib/api/generated/` split by tag (`mode: 'tags-split'`), `client: 'react-query'`, `httpClient: 'fetch'` via the `customFetcher` mutator.
- **Never edit files under `src/lib/api/generated/`.** Regenerate with `pnpm gen:api`. The `afterAllFilesWrite` hook runs `oxlint --fix` automatically.
- The mutator `src/lib/api/custom-fetcher.ts` (`customFetcher`) sets a default `Accept: application/json`, unwraps RFC 7807 `application/problem+json` errors into a typed `ApiError` (carrying `status` + `ProblemDetails`), and parses success bodies by content type. It exports `ErrorType`/`BodyType` so generated hooks default their `TError` to `ApiError`.
- Image and download endpoints are **not** consumed through the fetcher — use the URL builders in `src/lib/api/urls.ts` with plain `<img>`/`<a>` (the browser handles Accept negotiation and streaming). All relative paths must be URL-encoded (e.g. `/` → `%2F`).
- `useInfinite` is disabled in orval (page/pageSize casing mismatch); write manual `useInfiniteQuery` wrappers in `src/lib/api/content-queries.ts` instead. Follow that file's pattern: extract success data, coerce `number | string` fields with a `toNumber` helper, fixed `PAGE_SIZE = 50`.

## Authentication

- The backend gates all access — unauthenticated users never reach the SPA. The `SpaExtensions` middleware serves the built bundle only to authenticated users (cookie/oidc). Do **not** implement client-side auth checks or 401→login redirects in route guards. The `user` is still fetched via `GET /api/authentication/user` in the root route's `beforeLoad` (to get `name`/`isAdmin` for the app bar), but no redirect logic is needed — a 401 there means the session expired mid-session and is handled by the global `QueryClient` `onError` handler (Phase 8), not by route guards.

## Components (shadcn on base-ui)

- Components live in `src/components/ui/`, built on `@base-ui/react` primitives (not Radix), styled with `class-variance-authority` (`cva`) and the `cn` helper from `src/lib/utils.ts` (`twMerge(clsx(...))`).
- Use the **default export** pattern for components (see `button.tsx`): declare the `cva` variants separately, spread props onto the base-ui primitive, attach `data-slot`, and expose variants as a static property (`Button.buttonVariants = buttonVariants`).
- Tailwind v4 (`@tailwindcss/vite` plugin). Dark mode is class-based: toggle `dark` on `<html>` (see `src/lib/theme.ts`); CSS uses `@custom-variant dark (&:is(.dark *))`.
- Theme resolution (`src/lib/theme.ts`): explicit `localStorage["theme"]` → system `prefers-color-scheme` → default dark. Default export of theme functions; `Theme = 'light' | 'dark'`.

## Code style

- Follow oxlint. TypeScript strict; `tsconfig.app.json` / `tsconfig.node.json` split.
- Use the React Compiler (enabled via `babel-plugin-react-compiler` + `@rolldown/plugin-babel` in `vite.config.ts`) — avoid manual memoization unless profiling shows a need.
- Prefer named exports for utilities/hooks, default exports for UI components.
- Keep JSDoc on exported modules/functions that document non-obvious contracts (the codebase uses block-comment headers per module).

## Verification

Before considering a frontend task complete, run from `/app/frontend`:

1. `pnpm lint` (oxlint; `oxlint --fix` to auto-fix)
2. `pnpm test`
3. `pnpm build` (regenerates the API client, type-checks, and builds)
